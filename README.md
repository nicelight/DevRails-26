# DevRails Nav 27 — навигация по AI-разработке в DSH

DevRails помогает превратить идею в работающий проект и сохранить понятное
состояние разработки между сессиями. Навигация строится вокруг привычных
предметных операций: уточнить продукт, спланировать фичу, выполнить задачу,
проверить результат или вернуться к владельцу требования.

В этой ветке адаптированы 37 команд, общие workflow-контракты, роли, шаблоны
и проверки Memory Bank. Реализован внешний DSH-пакет с контроллером,
схематичной картой и Side-консультациями. [Запуск и установка](docs/nav27/QUICKSTART.md),
[проверенные сценарии и границы](docs/nav27/ACCEPTANCE.md).
Итог семантической приёмки — в [SEMANTIC_ACCEPTANCE.md](docs/nav27/SEMANTIC_ACCEPTANCE.md).
[DEVRAILS_NAV_27.md](DEVRAILS_NAV_27.md) сохраняет решения пользователя и
визуальный контракт. [Архитектура](docs/nav27/ARCHITECTURE.md),
[план реализации](docs/nav27/IMPLEMENTATION_PLAN.md) и
[source-проверка архитектуры](docs/nav27/ARCHITECTURE_ACCEPTANCE.md) согласованы
с plugin-only и [настройками на станциях](docs/nav27/SEMANTIC_STATION_SETTINGS_RESULT.md).
Native integration и browser-проверки описаны в отчёте приёмки; реальный provider
и все 37 команд end-to-end не проверены.

## Как устроена работа

Модели выполняют предметную работу: понимают требования, проектируют,
реализуют, проверяют и предлагают решения. Host управляет очередью,
запуском через штатные механизмы DSH, состояниями задач и восстановлением.
Название модели не выбирает внешний агентный CLI. Роли, модели и reasoning
задаются настройками; обязательного fanout или незаменяемого Judge нет.

Каждая операция возвращает один короткий структурированный feedback:
можно продолжать или требуется решение. Предметный результат и verdict
проверки остаются отдельными. Предлагаемые поля и native DSH transport определены
в спецификациях и реализованы в `packages/nav27`.

В обычном режиме нестандартный возврат, repair или консультация на основном
пути ожидают решения пользователя: согласия в основном чате либо зелёного
для конкретного предложения. Молчание и неполный ответ не являются согласием;
зелёный не создаёт отсутствующие факты. `/autonomous` принимает семантические
решения во всём запуске, включая дальнейший `/autopilot`, но не снимает
ручной красный, Pause, Stop или ограничения доступа.

## Путь от идеи к результату

Типичный путь, из которого выполняются только применимые выбранные операции:

```text
Идея → grill-me → constitution → write-prd
     → spec-init → prd-to-features → review-feat-plan
     → spec-design → нужная Foundation
     → feature-to-tasks FT-NNN → review-tasks-plan
     → exe TASK-… → выбранные verify / red-verify → завершение
```

Ясный PRD не требует повторного интервью. Для существующего проекта
`/map-codebase` сохраняет фактический baseline и возвращает работу к уже
переданному PRD/delta. Foundation — только необходимый executable baseline;
`FT-000` использует ту же очередь задач. Отдельный integrated proof gate
условен, реальные зависимости от baseline сохраняются.

`/feature-to-tasks` планирует одну продуктовую фичу. `/autopilot` работает
с подготовленной продуктовой очередью; `/autonomous` охватывает весь путь,
включая нужную Foundation. `/multipilot` и `/multiagentic` добавляют выбранные
консультации Judge к этим же контрактам.

## Проверки и завершение

Проверки, участники и отчёты включаются независимо. Можно отключить основной
verify и оставить других участников без скрытого replacement main. Code-only
review возвращает кандидаты findings, а не functional PASS. При всех verify off
получается `skipped`, отчёт не нужен; реализованная задача может стать `done`,
но это не доказывает verified acceptance.

Red-verify отключаем и может самостоятельно исследовать реализацию с честной
отметкой об отсутствии functional proof. Локальные checks внутри `/exe`
имеют отдельную настройку, по умолчанию включены. Это рабочие defaults,
которые можно изменить. Уровни T0–T3 определяют риск и глубину выбранного proof,
а не неотключаемый набор проверок или файлов.

Фактический FAIL/REJECT не стирается новым skip: дальнейшая работа требует
scoped решения о repair или продолжении. Memory Bank сохраняет выбранные
операции, результаты, частичные эффекты и ближайший handoff. Потеря сессии
не требует повторять завершённую реализацию или выдумывать историческое proof.

## Что уже можно проверить локально

Существующий installer проверяет доставку source-only framework. Он пока
генерирует legacy `.agents/skills/` и `.claude/skills/`; **это не DSH adapter**
и не обещание готового Nav runtime.

```bash
nav_target="$(mktemp -d)"
node scripts/install-framework.mjs --bootstrap --target "$nav_target" --yes
```

`--install-only` доставляет команды без Memory Bank; `--bootstrap` добавляет
skeleton, роли, workflows, шаблоны, lint/doctor. `--bootstrap --sync` обновляет
managed файлы с сохранением project-owned решений и evidence. Установка
отказывается перезаписывать неизвестные пользовательские skill-каталоги.
Прямой `npx skills add` этого source-only репозитория не поддерживается.
